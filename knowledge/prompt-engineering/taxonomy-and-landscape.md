# 技法体系の全体像

プロンプトエンジニアリングの技法を網羅的に整理しようとした学術サーベイが、この分野には複数存在する。zero-shot、few-shot、chain-of-thought、self-consistency、ReAct、chain of code——数十種類にのぼる技法を、タキソノミーとしてまとめる試みである。

個別の技法を1つずつ追うより、まず**地図**を持つほうが学習効率がよい。このファイルでは代表的な2本のサーベイを並べ、そこから実務者が何を読み取ればよいかを扱う。技法そのものの使い方は[基本技法](./core-techniques.md)にある。

## 2つのサーベイ

### Sahooら：41技法以上をアプリケーション領域別に

1本目は、arXivに公開されたSahooらのサーベイ論文である（[Sahooらのサーベイ](../sources/article-pe-pe-survey-sahoo.md)）。

同論文は、多様なプロンプトエンジニアリング手法・技法についての体系的な整理と理解がこれまで欠けていたという課題認識を示し、そのギャップに応えるためアプリケーション領域別に分類した構造化された概要を提供すると述べている。扱う技法は**41種類以上**であり、各プロンプティングアプローチについて、その手法の詳細、アプリケーション、関わるモデル、使用されたデータセットの要約を提供するとしている。加えて各アプローチの強みと限界にも踏み込み、タキソノミー図と、データセット・モデル・各技法の重要ポイントをまとめた表を含むと説明している。

同論文はまた、プロンプトエンジニアリングという概念が当初LLMにおいて研究・普及し、その後VLM（視覚言語モデル）へと拡張されたという流れも整理している。

### Schulhoffら：PRISMAで58技法を体系化

2本目は、同じくarXivの「The Prompt Report」である（[The Prompt Report](../sources/article-pe-prompt-report.md)）。

同論文は、プロンプティングは新興分野であり、既存の用語や技法のごく一部しか実務者に広く知られていないという課題認識のもと、PRISMAプロセスに基づく機械支援の**系統的レビュー**を実施したとしている。成果として、33の用語からなる語彙体系、**58種類**のLLMプロンプティング技法のタキソノミー、そして他モダリティ向けの40技法を提示するとし、これらの集大成として本サーベイをプロンプトエンジニアリングに関する「これまでで最も包括的なサーベイ」であると位置づけている。目的は、どのプロンプティング技法を採用すべきかを検討する際のコミュニティ向けのロードマップを提供することにあると説明している。著者らはLearnPrompting.orgで用語と技法の最新リストを継続的に維持しているとも述べている。

なお、この2本はいずれもarXivに公開されたプレプリントであり、配信経路としては同一である。ここで示す「技法体系の全体像」は、独立した2つの研究グループによる整理が一致している範囲の話として読むのが妥当だろう。

## 41と58の違いは矛盾ではない

同じ分野を整理して数が違う。これは片方が間違っているのではなく、**スコープと粒度の設定が違う**ためである。そして、そのスコープの切り方こそが、初心者にとって最も有用な情報になっている。

[The Prompt Report](../sources/article-pe-prompt-report.md)は、扱う対象を意図的に絞り込んだとして、3つの限定を明示している。

1. **cloze promptsではなくprefix promptsに焦点を当てる** — 現代のLLMのTransformerアーキテクチャがprefix promptsを広く採用し、開発者・研究者双方に堅牢なサポートを提供しているため
2. **soft（continuous）promptsを除外し、hard（discrete）promptsに絞る** — 勾配ベースの更新（すなわちファインチューニング）を伴うものを外し、モデルの語彙に対応するトークンのみで構成されるものを扱う
3. **task-agnosticな技法のみを研究対象とする** — 専門的でない読者にも近づきやすく、扱う範囲を管理可能な規模に保つため

この3つの限定は、そのまま**我々が日常で書いているプロンプトの定義**でもある。文章の穴埋め（cloze）ではなく前から書き足していく形式であり、モデルの重みをいじらず普通の言葉で書き、特定タスク専用ではない。同論文が扱う58技法は、この意味でチャット型AIを使う立場からそのまま射程に入る。

逆に言えば、検索して出てくる技法のなかには、ファインチューニングを前提とするものや特定タスク専用のものが混じっている。「試したが効かなかった」ときは、その技法が自分の使い方の外側にあるだけ、という場合がある。

## 地図の中心にあるもの

数十の技法があるとはいえ、中心は動かない。[Sahooらのサーベイ](../sources/article-pe-pe-survey-sahoo.md)は、現代のプロンプトエンジニアリングの風景が、zero-shotやfew-shot promptingのような**基礎的な手法**から、「chain of code」promptingのようなより複雑なアプローチまで、幅広い技法のスペクトルにまたがっていると説明している。

体系の入口はzero-shotとfew-shotであり、そこから枝分かれしていく構造になっている。この2つは[基本技法](./core-techniques.md)で扱った。地図の読み方としては、**まず中心の2つを押さえ、必要になった方向にだけ歩く**のが正しい。41なり58なりを端から覚える読み方は、サーベイ論文の使い方としても想定されていない。

## プロンプトとプロンプトテンプレート

[The Prompt Report](../sources/article-pe-prompt-report.md)によるプロンプトの基礎的な定義（生成AIモデルへの入力であり、テキスト・画像・音声などから構成されうるという説明）と、そこから派生する**プロンプトテンプレート**（変数を含む関数として構築されるという定式化）は、[プロンプトの構造](./prompt-anatomy.md)で扱った。実務上の含意は明確で、**同じ依頼を繰り返すならプロンプトは書き捨てずテンプレート化すべき**ということになる。

## 地図の外周：エージェント・評価・安全性

サーベイが扱う範囲は、単発の指示の書き方にとどまらない。[The Prompt Report](../sources/article-pe-prompt-report.md)は、対象範囲を次のように広げたと述べている。

- **多言語** — 既存文献の多くが英語のみを対象としているのに対し、多言語プロンプティング技法も議論する
- **マルチモーダル** — プロンプトが画像などのメディアを含む形式が急速に拡大していることを受けて範囲を広げた。多言語・マルチモーダルの技法の多くは、英語テキストのみを扱う技法を直接的に拡張したものだとしている
- **エージェント** — プロンプティング技法が複雑化するにつれ、インターネット閲覧や計算機といった外部ツールを組み込むようになってきたとし、こうしたタイプの技法を指す用語として「エージェント」を用いる
- **評価** — エージェントおよびプロンプティング技法の出力を正確に評価し、幻覚（hallucination）を避けるための評価手法を論じる
- **安全性** — 企業やユーザーへの被害リスクを低減するプロンプト設計のためのセキュリティおよび安全対策を扱う

注目したいのは3つ目である。**外部ツールを使い始めた時点で、それは「エージェント」という別の名前で呼ばれる領域に入る**、という線引きが学術サーベイの側でも明示されている。チャットにプロンプトを打つ話と、AIに手足を持たせて動かす話は地続きだが、必要な設計は変わる。この先の話は[ループエンジニアリング](./loop-engineering.md)で扱う。

4つ目・5つ目も実務では外せない。技法を洗練させても出力が正しいとは限らず、評価の仕組みと安全対策は別途必要になる、という認識がサーベイの構成そのものに織り込まれている。

## 検証はどう行われているか

[The Prompt Report](../sources/article-pe-prompt-report.md)は、プロンプティング技法を実際に適用した2つのケーススタディを実施したとしている。1つ目は、広く使われているベンチマークであるMMLUに対して幅広いプロンプティング技法をテストするもの。2つ目は、実世界における重要なユースケースを対象とした手動プロンプトエンジニアリングの詳細な事例研究であり、支援を求める個人のテキストの中から「絶望的な焦燥感（frantic hopelessness）」——自殺危機を示す代表的なシグナルの一つ——を識別する試みだとしている。

ベンチマーク上の比較と、成否が現実に影響する実タスクの両方を置いている構成である。技法の効果を語るときに「どのタスクで測ったのか」を確認する癖は、実務でも持っておいたほうがよい。ある技法がMMLUで効いたことは、自社の議事録要約で効くことを意味しない。

## 実務者としてのこの地図の使い方

まとめると、次の順で使うのが現実的である。

1. **[基本技法](./core-techniques.md)を回す** — zero-shotで始め、足りなければfew-shot・役割設定を足す
2. **症状を特定する** — 形式がぶれるのか、前提を外すのか、推論が浅いのか、事実が怪しいのか
3. **症状に対応する領域だけをサーベイで引く** — 41技法・58技法のリストは、通読する教科書ではなく**辞書**として使う

技法名を多く知っていることと、出力の質を上げられることは別である。地図の価値は、覚える量を増やすことではなく、**いま自分がどこにいて、どの方向に歩けばよいかが分かる**ことにある。
