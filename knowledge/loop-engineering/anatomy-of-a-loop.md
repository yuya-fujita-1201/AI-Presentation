# ループの解剖——5段階・4ポイント・2層・3つの速度

「ループを設計する」と言われても、何を設計すればいいのかは言葉だけでは分からない。この記事では、資料が語るループの中身を4つの角度から開けていく。**1周の中身（5段階）／設計時に決めること（4ポイント）／層の構造（2層）／回る速さ（3種類）** の4つである。最後に1枚の図として重ね合わせる。

## 1周の中身——5つの段階

Kiloの記事は、ループの1周を5つの段階に分けて説明している（[記事: Kilo](../sources/article-le-kilo-loop-engineering-definition.md)）。

1. **Intent（意図）** — 開発者またはシステムが、達成すべき目標を定義する
2. **Context（文脈）** — コード・ドキュメント・エラー・ログなど、関連情報を集める
3. **Action（行動）** — ファイル編集・コマンド実行・ツール呼び出しといった操作を実行する
4. **Observation（観察）** — テスト結果・コンパイラエラー・diff・レビューコメントといった結果を取得する
5. **Adjustment（調整）** — 観察結果をもとに計画を更新し、反復を継続する

MindStudioの記事も、ほぼ同じ形を別の言葉で描いている。すなわち、AIエージェントが**観察・推論・行動・評価**のサイクルを繰り返し実行し、定義された目標に達するまで継続する方法論だ、という定義である（[記事: MindStudio](../sources/article-le-loop-engineering-mindstudio.md)）。段階の数と名前は違うが、**「情報を集める→動く→結果を見る→次を決める」という骨格は独立した2つの記事で一致している**。

初めて読むときに引っかかりやすいのは4の Observation である。チャットAIの使い方では、出力を読んで良し悪しを判断するのは人間だった。ループでは、この段階に**機械が読める信号**が入る。テストの合否、ビルドの終了コード、スクリーンショット——ここに何を置けるかがループを組めるかどうかを決める。この論点は[検証の設計](./verification-design.md)で単独に扱う。

## 設計時に決める4つのポイント

1周の中身が分かっても、設計者が手を動かして決めるべき項目はまた別である。まさおAIじっくり解説chの動画は、ループを設計するうえで押さえるべき概念として4つを挙げている（[動画: まさおAIじっくり解説ch](../sources/video-le-loop-design-four-points.md)、聞き取り）。

| # | ポイント | 決めること |
|---|---|---|
| 1 | ゴールの明確化 | **計測できる形で**ゴールを設定する。LLMジャッジや複数のLLMが合格と判定するまで、といった方式も例として挙げている |
| 2 | エージェントの割り当て | 目標に対してどのエージェントに実行させるかを決める。スキルやサブエージェント定義が該当するとしている |
| 3 | 進捗の検証 | todolistやタスク管理ツールで、検証が終わったかどうかの進捗を確認する |
| 4 | 継続条件の判定 | 「70点ぐらいのコンテンツだから合格しない」と判断された場合にリトライが走る、というように継続・終了の条件を区切る |

この4点は当該動画の自動字幕からの聞き取りに基づく整理であり、業界標準の枠組みとして確立しているわけではない。ただし1と4は、後述するとおり他の資料とも重なる。

同動画は注意点として、**変なゴールや変な検証器を作ってしまうと、成果物が本来意図するものからずれていく**とも指摘している（聞き取り）。ループは方向を疑わずに加速する装置なので、向きを決める1と4を間違えると、間違った方向に速く進むことになる。

## 器・目標・部品——3つの構成要素

MindStudioの記事は、これを実装の語彙で3つに分けている（[記事: MindStudio](../sources/article-le-loop-engineering-mindstudio.md)）。

- **/loop** — 一連のアクション実行を繰り返すメカニズム。有界（N回実行）または条件付き（条件が真になるまで）のいずれかで動作する
- **/goal** — エージェントが達成すべき成功条件を定義するもの。成功状態・制約・優先順位シグナルを含む
- **/routines** — モジュール化された再利用可能なアクション配列。データ取得・要約・エスカレーション・通知などの個別タスクを構成する

**繰り返す器（/loop）と、止まる条件（/goal）と、中で動く部品（/routines）は別物である**——この分離が重要で、記事は「最も一般的な失敗は、ループから始めてゴールを後で考えることだ」という趣旨を明記している。器だけ先に作っても、止め方が決まっていなければ無期限に実行されるか恣意的に終了する、というのが同記事の主張である。詳細は[ゴールと停止条件の設計](./goal-and-stop-conditions.md)で扱う。

## 層の構造——インナーループとアウターループ

ループは1本ではない。RUNTEQの動画は、内側の**インナーループ**と外側の**アウターループ**という2層があると説明している（[動画: RUNTEQ](../sources/video-pe-loop-engineering-5plus1-parts.md)、聞き取り）。

**インナーループ**は、1つのタスクの中で編集・テスト作成・テスト実行・失敗検知・修正・再実行というサイクルを、通過するまで繰り返すものだとしている。同動画はこれによって、「完了しました」と言いながら実際には直っていない、という従来のAIコーディングの不満を解消できるとしている。

**アウターループ**は、1つのインナーループ（1機能・1セッション相当）だけでは要件を満たせないため、複数のタスクをまたいで回していくものだとしている。設計上のポイントは、**あるタスクでの失敗の教訓を次のタスクに引き継ぐ**ことだという。

同動画は、自作したアウターループ用スキル「エピックフロー」を実装例として紹介している。大きな要件をプランナーが分解し、依存関係・受け入れ条件・目的を決める→**ここで1回人間の承認を挟む**→メインエージェントがタスクを1つずつ実行→1タスク完了ごとにブランチへマージ→全タスク完了後の最終プルリクエストで**再び人間が確認する**、という流れである（聞き取り）。人間の承認が分解直後と最終PR確認の2箇所に置かれており、アウターループでも人間が完全に手を離すわけではない設計の一例になっている。

同動画は検証について、テストだけでなくセキュリティリスク・コードの品質・仕様との食い違いなど、複数の観点のレビューを重ねるほど検証の精度が上がるとも述べている（聞き取り）。

## 回る速さ——3つの入れ子ループ

層をさらに外へ広げた整理もある。安野貴博氏の動画は、AI研究者のアンドリュー・ン氏が、ループは**速さの異なる3種類が入れ子構造になっている**と整理していると紹介している（[動画: 安野貴博の自由研究](../sources/video-pe-loop-engineering-overview.md)、聞き取り）。

1. **最も速いループ（数分刻み）** — 仕様とテスト用データを渡すと、エージェントが実装・テスト・修正を繰り返す部分
2. **監督ループ（数十分〜数時間）** — 人間が介入し、出てきた成果を見て方向性を修正する
3. **外部フィードバックループ（数時間〜数週間）** — 友人や一部ユーザーに見せる、本番でABテストする、といった外からの気づきが最も速いループへ反映されていく

RUNTEQ動画の2層と、この3種類は語彙も出所も違うが、**「ループは1層ではなく入れ子である」という構造は共通している**。RUNTEQのインナーループが1つ目に、アウターループが2つ目におおむね対応すると読める。

この整理から実務的に効く帰結が1つある。[ループエンジニアリングとは何か](./what-is-loop-engineering.md)で触れた Human on the Loop とは、**最も内側のループから人間が抜けることであって、すべてのループから人間が消えることではない**。2つ目の監督ループは、むしろ人間の居場所として設計されている。同動画は、人間がループに残る理由についてン氏の仮説も紹介しており、それは人間のセンスという貴重な資源があるからではなく、ユーザーや製品が使われる状況についてAIが知らない情報を人間が持っており、その情報量の差を埋めているに過ぎない、というものだとしている（聞き取り）。

## 1枚に重ねる

4つの角度を重ねると、次のような像になる。

```
[外部フィードバックループ]  数時間〜数週間  ユーザー・本番からの気づき
  └ [アウターループ／監督ループ]  数十分〜数時間  タスクをまたぐ・人間が方向を修正
      └ [インナーループ]  数分刻み  1タスクを通過するまで
          └ 1周 = Intent → Context → Action → Observation → Adjustment
             設計で決めるもの = ゴール／担当エージェント／進捗検証／継続条件
```

内側ほど速く、外側ほど遅い。そして**内側ほど自動化の対象で、外側ほど人間の居場所**になる。ループを設計するとは、この階層のどこに自分が立ち、どこを機械に渡すかを決めることだと言い換えられる。

## まとめ

- ループの1周は、Intent（意図）→Context（文脈）→Action（行動）→Observation（観察）→Adjustment（調整）の5段階に分けられる
- 設計時に決める4ポイントは、ゴールの明確化・エージェントの割り当て・進捗の検証・継続条件の判定である
- 器（/loop）・目標（/goal）・部品（/routines）は別物であり、ゴールを後回しにしてループから作り始めるのが最も一般的な失敗である
- ループには内側のインナーループと外側のアウターループの2層があり、アウターループは失敗の教訓を次のタスクに引き継ぐ設計が要になる
- さらに広く見ると、速さの異なる3つの入れ子ループ（実装ループ・監督ループ・外部フィードバックループ）として整理できる
- Human on the Loopとは最も内側のループから人間が抜けることであり、すべてのループから人間が消えることではない
