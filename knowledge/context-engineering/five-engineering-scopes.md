# 5つのエンジニアリングのスコープ差

ここ数年で「プロンプトエンジニアリング」「コンテキストエンジニアリング」「ハーネスエンジニアリング」「ループエンジニアリング」「グラフエンジニアリング」と、似た響きの用語が一気に増えた。新しく学ぶ人にとって最初の壁は、**これらが順番に置き換わっていく流行語なのか、それとも同時に成り立つ別々の話なのか**が分からないことである。

結論から言えば、後者として捉えるのが実用的である。

## 目的は同じ、違うのはスコープ

5つのエンジニアリングの目的はすべて共通しており、AIの回答の質を上げることである。違いは目的ではなく**スコープ（対象範囲）**だ——という整理を、動画「[Loop, Harness, Prompt, Context, Graph Engineeringの徹底ガイド](../sources/video-pe-five-engineering-stages.md)」（auto字幕からの聞き取り。以下このページで同動画を出所とする記述は同様）は提示している。同動画はそれぞれを次のように区別している。

| スコープ | 何を設計するか | 人間の仕事に例えると |
|---|---|---|
| プロンプト | 指示を磨く | 仕事の頼み方 |
| コンテキスト | 渡す情報を選ぶ | 渡す資料選び |
| ハーネス | 動く環境を整える | 机・道具・権限の整備 |
| ループ | 時間軸で動きを回す | 赤ペン添削の反復 |
| グラフ | 構造で組む | チームでの分業 |

同動画は、前半3つ（プロンプト・コンテキスト・ハーネス）を材料と環境に関わる部分、後半2つ（ループ・グラフ）を動きの設計に関わる部分として分類している。

別の解説動画「[AIの性能は7割が環境構築で決まる](../sources/video-ce-harness-context-setup.md)」（同じくauto字幕からの聞き取り）も、プロンプト→コンテキスト→ハーネスを縦の3段階、ループとグラフを「どう回すか」という別軸の横2軸として、ほぼ同じ形に整理している。ただし同動画は、**呼称は発信者によって揺れており厳密に捉えず参考程度でよい**とも明言しており、この点は本教材の立場と一致する。

## 置き換えではなく入れ子

重要なのは、新しい層が古い層を無効にしないことである。

前掲の徹底ガイド動画は、5つはバラバラの技術ではなく、**グラフの1マスの中にプロンプトとコンテキストが含まれ、そのマス同士をループが回し、全体をハーネスが環境として支える**という入れ子構造で捉えるべきだとしている（[出典](../sources/video-pe-five-engineering-stages.md)）。

「プロンプトはオワコン」といった言説は各所で見られるが、[ハーネス解説動画](../sources/video-ce-harness-context-setup.md)（auto字幕からの聞き取り）は、プロンプトエンジニアリングは廃れてはおらず、最近のエージェントにおいては複数ある工夫の1つという位置づけになったと述べている。同動画は、各社の傾向として指示はなるべく短く簡潔にした方が性能が上がる方向に収束しつつあるとしているが、特定モデルの公式なガイドラインとして断定はできない。

また、[コンテキストエンジニアリング入門動画](../sources/video-ce-context-layers-intro.md)は、コンテキストエンジニアリングをプロンプトエンジニアリングの上位概念であり、プロンプトはコンテキストの一部に含まれるとしている。これも解説者の整理であって、業界で合意された定義ではない。**上位・下位という言い方は、包含関係の説明としては分かりやすいが、優劣の話ではない。**

## 症状からどこを直すかを決める

5つを全部いっぺんに意識するのはやりすぎである。徹底ガイド動画は、まずは通常のプロンプト・コンテキストの範囲で試し、精度が足りないと感じた**症状に応じて**追加の考え方を導入すべきだと助言している。同動画が挙げる症状別の目安は次のとおり。

- **意図と違う結果が返る** → プロンプトを見直す
- **前提を忘れる** → コンテキストを見直す
- **手作業の事故が怖い** → ハーネス（権限・承認フロー）を見直す
- **品質が安定しない** → ループ（検証の反復）を見直す
- **タスクが大きすぎて崩れる** → グラフ（分業）を見直す

この切り分けは、本教材が5層を「境界を証明する分類」ではなく「失敗時にどこを直すかを探す地図」として使う理由そのものである。実際のシステムでは層は重なる。たとえばツール定義はハーネスの部品であると同時に、モデルが読むコンテキストでもある。

## 本教材での扱い

以上の5層整理は、**複数の解説者が近い形で提示しているものの、いずれもauto字幕由来の解説であり、標準規格でも一次資料に基づく定義でもない**。本教材では理解と切り分けの補助線として採用し、個々の技術的主張（注意の有限性、検索の効き方、圧縮の仕様など）については公式ドキュメントや原著論文を根拠として別ファイルで扱う。

なお、同じ「5層」という呼称を、コンテキストという1つの層をシステムプロンプト〜会話履歴にさらに分解する[コンテキストの層と介入点](./context-layers-and-intervention.md)でも使っているが、両者は別の切り口であり、指す対象が異なる。
