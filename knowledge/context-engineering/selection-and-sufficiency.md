# コンテキストの選別と十分性

コンテキスト設計の中心は、資料を集めることではなく**選ぶこと**である。Anthropicも、目標達成の確率を高める小さな高シグナル集合を目指しつつ、「小さい」を単なる短さと取り違えないよう説明している（[Effective context engineering](../sources/article-ce-anthropic-effective-context-engineering.md)）。情報が少なければ前提を推測し、多すぎれば重要な根拠が埋もれる。必要なものだけを残す判断には、次の4つの観点を使える。

1. **必要性** — この情報がないと、判断、生成、検証のどれができなくなるか。
2. **十分性** — この情報だけで、重要な例外や判断基準まで扱えるか。
3. **信頼性** — 誰が、どの方法で作り、どこまで確認した情報か。
4. **鮮度** — 今回の時点と対象に有効な版か。更新後に変わる箇所はないか。

この4項目は**本教材の選別用チェックリストであり、標準化された評価規格ではない**。点数を付ければ自動的に正解になるものでもない。何を残し、何を捨てたかを説明可能にするための問いである。

## 必要性——「念のため」を疑う

各資料について「この資料がなければ、どの判断ができないか」を問う。答えが出ないものは、最初から入れず、必要時に取得できる索引だけを渡す候補になる。

ただし、最終出力に直接使わない情報でも必要になることがある。禁止事項、反例、用語定義、過去の失敗、検証方法は、誤った方向へ進むことを防ぐために必要である。必要性は「引用されるか」ではなく、**行動や判定を変えるか**で見る。

## 十分性——長さではなく判断可能性

十分性は「資料を全部入れたか」ではない。目的に対して必要な判断ができるかである。

たとえば売上報告を分析するのに合計額だけでは不十分かもしれない。比較期間、集計定義、欠損、キャンペーン有無が必要になる。一方、明細全件が常に必要とは限らない。先に集計表を渡し、異常のある区分だけ明細を取得する方法もある。

Googleは、質問に答えるための情報がコンテキストに十分含まれているかを別に評価する研究を公開している。これは、回答の流暢さと、根拠が足りているかを分けて考える重要性を示す（[Google: Sufficient context for RAG](../sources/article-ce-google-sufficient-context-rag.md)）。ただし、十分性の判定自体もモデルや評価方法に依存する。高い判定を最終保証として使ってはいけない。

## 信頼性——内容より先に出所を見る

信頼性を判断する材料には、次がある。

- 正本か、草案か、第三者の要約か。
- 一次資料か、転載か、AI生成の再要約か。
- 誰が確認し、どの範囲が未確認か。
- 数値の定義、母数、集計時刻が明示されているか。
- 他の資料と矛盾したときの優先順位が決まっているか。

AIが以前作った要約は、便利だが原文と同じ証拠ではない。要約を再要約すると誤差が蓄積する。重要な結論では正本へ戻れる参照を残す。

## 鮮度——「最新」と「対象時点」を分ける

最新の資料が常に正しいとは限らない。過去時点の障害を分析するなら、当時の設定や規約が必要である。鮮度は「一番新しいか」ではなく、**今回扱う時点に適用されるか**で判断する。

製品のモデル名、コンテキスト容量、料金、キャッシュTTL、保持日数、データ利用方針は変わりやすい。本教材では固定値として一般化しない。必要なときに、対象製品の公式情報を現在時点で確認し、取得日と適用範囲を添える。

## 競合する情報の扱い

矛盾を見つけたら、AIに自然に統合させない。次の順で扱う。

1. 矛盾する箇所を並べる。
2. 各資料の出所、版、対象時点、確定状態を確認する。
3. 優先規則があれば適用する。
4. 決められない場合は、両論と影響を残して人に確認する。

「もっとも詳しい記述」や「最後に書かれた記述」を自動的に正とするのは危険である。

Microsoftの教材が挙げるpoisoning、distraction、confusion、clashという失敗分類も、信頼できない情報、無関係な情報、役割の混線、矛盾する情報を別々に診断する補助線になる（[Microsoft: Context Engineering for AI Agents](../sources/course-ce-microsoft-context-engineering.md)）。名称を暗記するより、どの情報を採用・保留・不足へ移すべきかに使う。

## 選別記録のテンプレート

```text
[context-selection]
目的:
今回の判断:

採用する情報:
- 資料 / 箇所:
  必要な理由:
  信頼性・確定状態:
  対象時点:

保留・除外する情報:
- 資料 / 箇所:
  理由: 重複 / 対象外 / 古い / 出所不明 / 矛盾未解決

不足している情報:
- 不足内容:
  ない場合の影響:
  取得方法または人への質問:
```

除外理由を残すと、後で目的が変わったときに再取得できる。「入れなかった」ことと「存在を知らなかった」ことも区別できる。
