# コンテキストの構成要素

チャット画面で利用者が入力した文章だけがコンテキストではない。AIが1回の応答を生成するとき、複数の情報源が一つの入力として組み合わされる。

## 推論時に入りうる情報

代表的な構成要素は次のとおりである。

- **システム・運用指示** — AIの役割、守るべきルール、利用可能な機能。
- **現在の依頼** — 今回してほしい作業、完了条件、出力形式。
- **会話履歴** — 直前までの質問、回答、訂正、合意。
- **例** — 期待する入力と出力、避けたい例、評価基準。
- **外部資料** — 添付文書、コード、データ、検索・RAGで取得した断片。RAGの原型は外部の非パラメトリック記憶から取得した情報を生成へ渡す（[Lewis et al. 2020](../sources/paper-ce-rag-lewis-2020.md)）。
- **ツール情報** — ツール名、説明、引数、返ってきた結果やエラー。定義と結果の両方がコンテキストを消費する（[Anthropic: Manage tool context](../sources/docs-ce-anthropic-manage-tool-context.md)）。
- **状態・記憶** — 進捗、以前の決定、利用者の継続的な好み、作業ログ。

Anthropicの整理でも、コンテキストにはシステム指示、ツール、外部データ、メッセージ履歴などが含まれ、作業の進行に応じてその組み合わせが変わる（[Effective context engineering](../sources/article-ce-anthropic-effective-context-engineering.md)）。Microsoftの初心者向け教材も、instructions、knowledge、tools、history、preferencesをコンテキストの種類として整理している（[Microsoft: Context Engineering for AI Agents](../sources/course-ce-microsoft-context-engineering.md)）。GoogleのAgent Development Kitも、セッション、状態、メモリ、アーティファクトなどを別の役割として扱う。実装名は製品ごとに異なるが、**今の入力、継続状態、外部保存物を分ける**という考え方は移植できる（[Google ADK: Context architecture](../sources/article-ce-google-adk-context-architecture.md)）。

これらは同じ信頼度ではない。確定仕様と検索結果、利用者の発言とAI自身の前回要約、最新データと古いメモを混ぜると、矛盾したときに判断できない。内容だけでなく、**出所・更新日時・確定状態**を添える必要がある。

## 依頼を理解する5項目

チャット利用や業務依頼では、次の5項目で前提の抜けを探すと扱いやすい。

1. **目的** — 何の判断や行動のために出力を使うのか。
2. **読み手** — 誰が読み、何を知っていて、どの言葉が通じるのか。
3. **状況** — 何が起き、どこまで進み、なぜ今この依頼が必要なのか。
4. **制約** — 期限、形式、予算、禁止事項、権限、対象外は何か。
5. **既存資産** — 正本、過去成果、テンプレート、コード、データ、用語集は何か。

この5項目は**本教材が初心者向けの確認表として採用する整理であり、公式規格や業界標準ではない**。全項目を毎回長く書く必要もない。すでに共有済みで、最新性と出所を確認できるものは参照先だけでもよい。

## 5項目が出力をどう変えるか

「議事録を要約して」だけでは、AIは何を残すべきか決めにくい。

- 目的が「次回会議の準備」なら、未決事項と宿題を優先する。
- 読み手が「欠席した部長」なら、経緯と意思決定を短く補う。
- 状況が「正式決定前」なら、案と決定を分ける。
- 制約が「個人名を出さない」なら、担当を役割名に置き換える。
- 既存資産に「正式な決定ログ」があれば、議事録より優先して照合する。

同じ原文でも、必要な出力は変わる。背景を足す価値は文章を詳しくすることではなく、**何を残し、何を捨て、何を確認するかの判断基準を与えること**にある。

## 情報源にはラベルを付ける

資料を渡すときは、最低限次のラベルを付ける。

```text
[source]
名称: 障害報告書 v3
正本: はい
更新: 2026-08-13
状態: 事実確認済み
用途: 影響範囲と復旧時刻の根拠
注意: 原因は暫定。断定しない
```

ラベルがないと、AIは文章の流暢さから確度を推測するしかない。正式な資料が簡素で、古い草案が詳しい場合、詳しいほうに引かれる危険がある。出所の指定は、情報量を増やすより重要なことがある。

## 「入っている」と「使える」は別

資料を添付しただけで、必要な箇所が必ず使われるわけではない。文書が長い、関連箇所が散らばる、複数版が競合する、質問と資料の関係が曖昧、といった状態では利用しにくい。重要箇所の場所、今回使う章、参照優先順位を示すとよい。

一方、利用者が先に要約しすぎると、例外や反証材料を落とす。原文、抜粋、要約のどれを渡すかは、[選別と十分性](./selection-and-sufficiency.md)で扱う4つの観点から決める。
