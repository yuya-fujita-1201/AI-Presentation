## README作成から最初のコミットまで

## メインブランチ同士だとプルリクエストが作れない問題

- 2つのコミットができた状態で「プッシュして、その時にハブのメインに対してプルリクエストを出して欲しい」と依頼したところ、手元のパソコンでもGitHub上でもブランチ名が同じ「メイン」であるため、メインから同じ名前のブランチに対してプルリクエストを出すことはできない、という指摘がClaude Codeから返ってきたと動画は紹介している
- この対処として、講師は「イニシャルファイルズ」という別ブランチを作り、そこに先ほどの2つのコミットを移してからプッシュ・プルリクエスト作成を行う、という手順を実演している
- プルリクエストが作成されるとGitHub上に「プルリクエストが1」という表示が出て、変更内容（README.MDとメモファイルの追加）が確認できるようになり、「マージプルリクエスト」を実行するとメインブランチの記録に統合される、という流れが示されている

## 2つのブランチで同じ行を変更するとコンフリクトが起きる

- 続いて、安野さんと山田さんが別々のプルリクエストを送った場合を想定した実演として、新しい機能開発のために「4月」というブランチを作成し、その中の「メモ」ファイルの内容を「2026年5月です」から「2026年4月です」に書き換えてコミットし、プルリクエストを作成している

- 動画は、4月になる機能のプルリクエストはそのままマージに成功した一方、6月になる機能のプルリクエストは「マージはブロックされています」「このブランチには解決しないといけないコンフリクトが発生しています」とGitHub上に表示され、マージできなくなったと説明している
- 「リゾルブコンフリクト」を押すと、メインブランチ上では「4月」と書かれているのに自分のブランチでは「6月」と書かれている、という食い違いの箇所が表示される、としている

## Claude Codeと一緒にコンフリクトを解決する

- 動画は、この矛盾箇所をGitHub上からも解決できるとしつつ、あえてClaude Codeに戻って「3番のプルリクエストをマージしようと思ったらコンフリクトが発生していたので、これを解決したいと思っています。どうしたらいいですか？」と相談する手順を実演している
- Claude Codeは、先に4月がマージされていたため元の5月を6月に変えようとする変更が同じ行で衝突している、と状況を説明したうえで、解決手順として「ローカルで6月ブランチに最新のメインを取り込んでコンフリクトを解決してからプッシュしましょう」と提案してきた、としている
- コンフリクトを解決する方法にはマージとリベースの2通りがあるとしつつ、動画では一旦マージのやり方を採用している
- どちらの内容（4月か6月か）を正として残すかは最終的に人間が判断する必要があるとされており、動画では一度「6月を採用」と伝えたあとに「いや今は4月だったことに気づいたのでこのコンフリクトでは4月を正しいことにして」と判断を訂正する場面も示されている
- 最終的に4月の内容を残すことを選択し、コンフリクトを解決してプッシュすると、GitHub上でマージが可能な状態に戻り、無事にマージが完了したと動画は締めくくっている
