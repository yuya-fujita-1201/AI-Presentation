# 要点

## データベースとは何か（Excel・スプレッドシートの比喩）

- 動画は、データベースを「見た目を作るフロントエンド機能」と連携して動く、データを保存しておくための箱だと位置づけ、アプリを閉じても消えないデータをここに保存し、再起動時に読み込むことができると説明している
- 難しく聞こえるが実態はExcelやスプレッドシートに近いとしており、縦の列（カラム）と横の行（レコード）でデータを持つ点は共通しつつ、データベースの場合は列ごとに「数値しか入れられない」「文字列しか入れられない」「日付しか入れられない」といった厳格な型のルールがある点がExcelより「かっちりしている」と説明している
- よく使う基本キーワードとして、①テーブル（1枚の表。データベース内には複数のテーブルが存在し、ユーザー登録テーブル・スコアテーブル・設定テーブルのように用途ごとに分けて使う）、②レコード（横の行）、③カラム（縦の列）、④データ型（文字列型・数値型・日付型・真偽型など、列ごとに定められた型）の4つを挙げている

## Supabaseとは何か（BaaSとPostgresの関係）

- Supabaseは、データベースを使うために必要な裏側の設定をゼロから用意しなくても済むようにするサービスであり、こうした種類のサービスは「バックエンド・アズ・ア・サービス（BaaS）」と呼ばれると説明している
- データベースを一から用意しようとするとサーバー構築など専門知識が要求されるが、Supabaseを使えばデータベース機能に加えて、ログインの仕組み（認証）やAPIで繋ぐ仕組みなどもまとめて利用できるとしている
- Supabaseの基盤には、世界中で標準的に使われているPostgreSQL（動画内では「ポスグレ」と発音）が使われているとされ、ゼロからPostgreSQLを構築することもできるが、Supabase経由であればバイブコーディングを始めたばかりの人でも比較的手軽に扱えるとしている。AIに「Supabaseでこれをやっておいて」と指示するとそれなりに対応してくれるため、バイブコーディングとの相性が良いとも述べている

## 壊さない意識とSQLの危険な言葉

- 動画が「一番大事」と位置づけているのが、AIにデータベースを操作させる際にデータを意図せず消してしまったり、データの整合性を壊してしまったりしないよう気をつける「壊さない意識」であるとしている。AIが勝手にデータベースの中身を全部消してしまった、あるいは書き換えてしまったという話は度々耳にするとしている
- データベースへの命令はSQL（Structured Query Language）という言語で送られるとしたうえで、特に注意すべき「危険な言葉」として DELETE・UPDATE・WHERE の3つを挙げ、これらがSQL文に出てきたら注意度を上げるべきだとしている
- 具体例として、`DELETE FROM users WHERE ID=5` はID=5番のユーザーだけを削除する安全な例だが、WHERE句を付け忘れて `DELETE FROM users` と書いてしまうと、users テーブルの全レコードが一括で削除されてしまう、という危険性を説明している。同様にWHERE句の条件を `ID != 5`（ID=5以外）のように書き間違えると、対象範囲が意図と正反対になってしまう例も挙げている

## 事故を防ぐ3つの実践

- 動画は、データベースを扱う人が基本的に行っている事故防止策として3点を紹介している
  1. **SELECT文で事前確認する**: DELETEやUPDATEを実行する前に、同じ条件でSELECT文（例: `SELECT * FROM users WHERE ID=5`）を実行し、対象となるデータの件数や中身を確認する。仮にWHERE句の条件を書き間違えていても、想定より大幅に多い件数が返ってくることで異常に気づける
  2. **本番環境と開発環境を分ける**: 開発中はデータを壊しがちであるため、実際のユーザーが使う本番（プロダクション）環境と、その直前の検証を行うステージング環境、日常的な初期開発を行うデベロップメント（開発）環境を分けて運用すべきだとしている
  3. **バックアップ（ダンプデータ）を定期的に取得する**: 毎日決まった時間にバックアップを取っておけば、仮に本番データを誤って壊してしまっても、直前のバックアップ時点まで復旧できるとしている。Supabaseにはこうしたバックアップ機能が備わっており、Claude Codeに「今バックアップを取っておいて」と指示することもできるとしている
- これらを踏まえ、AIにどこまで作業を任せるかについては、何を消すか・何を書き換えるか・どの環境で実行しているか・バックアップがあるかを、最終的に人間が確認しながら一歩ずつ進めるべきだと締めくくっている
