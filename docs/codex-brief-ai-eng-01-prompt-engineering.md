## 2. 画像の共通仕様（全19枚に適用）

| 項目 | 指定 |
|---|---|

| 配色 | **`deck.json` の `meta.theme`（現在は `accenture-purple`）に準拠したテーマカラーのみ使用**。具体的な hex 値はここでは決め打ちせず、`templates/themes/accenture-purple.json` を読んで `primary` / `accent` 系のトークン値を取得すること。**清書時に `meta.theme` を切り替えればテーマカラーは変更可能だが、生成する挿絵は色を焼き込んだラスター画像（PNG）のため、テーマを切り替えても挿絵自体は自動で再配色されない**（テキストや背景など deck.json 側の描画要素だけが変わる）。この点は認識した上で、現行テーマの配色で確定させること |

| 密度 | **1枚につき伝える概念は1つだけ**。要素は5〜7個までに抑える。情報を詰め込むと 524px 幅で潰れて読めない |
| 一貫性 | 19枚を通して**同じ画風・同じ配色・同じ線の太さ**。人物を描く場合は全枚で同じ描き方（顔の描き込みは最小限、記号的に）。AIを表す場合もロボット等のモチーフを19枚で統一する |

## 3. 「良い図」の判断基準

3. 図の中の要素数が7個以下か？ 524px 幅に縮小しても各要素が識別できるか？
4. 他の18枚と並べたとき、同じシリーズに見えるか？
5. 文字が入っていないか？

## 5. 画像生成の進め方（推奨）

1. **まず3枚だけ試作する**：`fig-pe-04`（比喩の代表：鍵のかかった箱）、`fig-pe-07`（構造図の代表：4つの部品の帯）、`fig-pe-10`（人物同士のやり取りの代表：新入社員に説明する図）。この3枚で画風・配色・線の太さを固め、**プロンプトの共通部分をテンプレート化**する
2. 試作3枚をデッキに入れてビルドし、**524×378px に縮小された状態で識別できるか**を実際のプレビューPNGで確認する（ここで潰れるなら要素を減らす）
3. 画風が固まってから残り16枚を生成する
4. 図案（§4）の中には **1枚の画像内で Before/After や複数状態を比較する構図**が複数ある（`fig-pe-01`：小さいメモ／大きいメモの対比、`fig-pe-05`：曖昧／絞り込みの2段比較、`fig-pe-14`：左右の依頼書の対比、`fig-pe-16`：3つの容器の状態比較）。これらは1枚の中で左右・上下のバランスと画風が揃っているかに特に注意する
5. 生成した画像は `decks/01-prompt-engineering/assets/` に**同じファイル名で上書き**する（`deck.json` のパスは変更不要）

## 6. deck.json を触ってよい範囲

原則として文章は変更しない（発注者要望を反映して文言は確定済み）。ただし次だけは調整してよい。

- 画像を入れた結果、**キャプションと図の内容が食い違った場合の `caption` の修正**
- 図が大きすぎ/小さすぎる場合の該当スライドの `style.img` の調整（例: `{"img": {"w": 500, "h": 360}}`）
- 本文が枠から溢れた場合の `style.body.size` / `style.body.gap` の微調整

**やってはいけないこと**: スライドの追加・削除・順序変更、`title` / `punch` / `bullets` の書き換え、テーマ変更、`templates/` の編集。

文章に問題を見つけた場合は、直さずに**報告だけ**すること（発注者が判断する）。

## 7. ファクトシート（デッキが自ら断っている限定・留保を、図でも破らないこと）

`deck.json` の各スライドの `notes` には、内容の確度についての留保がすでに書かれている。図はこれらの留保を上書きするような断定表現をしないこと。

- 「5つの層」（プロンプト/コンテキスト/ハーネス/ループ/グラフ）は**解説動画による初心者向けの整理であり、業界の標準用語ではない**（スライド4）。図で優劣や唯一性を強調しすぎない
- 「型3：役割を与える」は**効果を裏づける比較データがない**と明記されている（スライド24）。図で精度向上を演出するような数値・グラフ的な説得力を加えない
- コンテキストの上限（一度に読める量）は**具体的な数値を出さない方針**（自動字幕からの聞き取りのため割愛、スライド30）。図中に目盛りや具体的な数字を書き込まない（そもそも文字は禁止）
- 技法の総数（41種類・58種類）は**資料によって異なり、どちらかを唯一の正解として図示しない**（スライド25）
- 「見本を3〜5個見せる」型は**多様性が欠けると副作用（意図しない癖まで守られる）が出る**と明記されている（スライド23）。`fig-pe-12` で見本カードを描く際、3枚が完全に同一の見た目にならないよう配慮する

**この一覧にない数値・固有名詞・実績を図に登場させないこと。**

## 9. 参考：`image_text` タイプの仕様

```json
{
  "type": "image_text",
  "title": "見出し",
  "punch": "一目で伝えたい一文（全幅・太字・アクセント色）",
  "bullets": ["本文（children で子項目も可）"],
  "path": "assets/figure.png",
  "caption": "図の下の補足",
  "image_side": "right"
}
```

- 領域: `title` / `rule` / `punch` / `body`（本文カラム 552×420px）/ `img`（**524×378px**）/ `caption` / `footer_l` / `footer_r`
- `image_side` を `"left"` にすると本文と図の左右が入れ替わる（`body` / `img` / `caption` の x 座標がキャンバス中心で反転する）
- 詳細は `docs/deck-schema.md` の `image_text` の項を参照
