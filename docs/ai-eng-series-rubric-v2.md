# AI Engineering シリーズ（01〜05）採点表 v2 — findings 駆動の減点方式

対象: `decks/0N-*/deck.json`（正本）、`build/contact/sheet-*.png`（全スライドの実見用コンタクトシート）、`assets/*.svg`（図中文字の確認用）。
想定読者: **AI初心者。チャットAIは触ったことがあるがエージェントは未経験。技術力は高くない業務担当者を含む。**
比較基準: `decks/01-prompt-engineering/` と `decks/02-context-engineering/`（人間レビューで「読みやすく、読者が本当に理解できる」と確認済みの正本）。

## 採点方式（v1 からの変更点）

- 採点者は**点数を書かない**。見つけた欠陥を findings として列挙する。点数はラッパーが `100 − Σ(大25・中5・小1)`（下限0）で計算し、**項目ごとに 80 以上で合格**
- 採点者は 3 名並列。項目ごとの点は 3 名の中央値。findings は和集合（重複は統合）を改善担当へ渡す
- 機械で測れるもの（ビルド・枚数・PPTX・**文字のはみ出し／重なり／罫線交差・SVG の明朝体フォールバック・closing 字数・Markdown 残留**）は機械ゲートの担当。採点者は報告しない
- 各 finding には **再現箇所（slide-NN と実際の文言の引用）** を必ず付ける。引用できない指摘は無効
- 採点指摘も誤りうる。改善担当は実物と突き合わせてから直す（rejected の権利がある）

## 重大度の定義

| 重大度 | 減点 | 定義 | 例 |
|---|---|---|---|
| 大 | 25 | **読者を止める／誤らせる／資料の信頼を損なう** | 事実誤り・出典の誤帰属／本編で初出の専門語が無説明で、その文が読めない／図が本文と矛盾（図6要素 vs 本文5項目）／用語の意味がスライド間で暗黙に切り替わる／未説明概念に依存する説明（前方参照）で理解不能／学習ゴール・定義スライドなど必須要素の欠落 |
| 中 | 5 | **読めるが、質が明確に落ちる** | AI定型句が目立つ／「AではなくB」型や体言止めが3連続／抽象論の直後に例がない難所／同じ概念に別の比喩／留保なしの軽い断定／図が飾り（本文を説明していない）／punch と caption が同じ主張の二段反復／図だけ英語ラベル |
| 小 | 1 | **気づく人は気づく** | 語尾の連続／記号・表記の不統一／1行の冗長／軽微な言い回しの硬さ |

目安: 大1件で不合格（75）。中は4件まで（80）。小は20件まで。

## 項目

| # | 項目 | 見るもの（減点の実体） |
|---|---|---|
| 1 | 初心者への適合 | 本編の初出専門語（エージェント・サブエージェント・リンター・型チェック・フック・ワークツリー・schema・正本・rubric・PASS 等）に平易な説明があるか／前方参照がないか／用語の意味が途中で変わらないか／非エンジニアが「自分の仕事の話」と思えるか（コード・Git・Claude Code 偏重でないか）。**理解度プローブ**: そのデッキの中核概念3つについて「スライドの文言だけから一文で定義できるか、何枚目で言えるようになるか」を実際に書く。本編冒頭7枚以内で「結局何なのか」に答えていなければ大 |
| 2 | 事実の正確性と誠実さ | 事実誤り／断定しすぎ（伝聞・聞き取り・推定の留保があるか）／数字に条件が付いているか／製品仕様をバージョン無視で断定していないか／5層モデルが「本シリーズ独自の整理」と明示されているか／出典が追えるか（出典スライドの有無、番号の整合） |
| 3 | 事例・比喩の適切さ | 難所（抽象概念の直後）に業務例（経費精算・議事録・稟議・アンケート等）があるか／比喩が説明対象と構造対応しているか／同じ概念に別々の比喩が当たっていないか／「優秀な新入社員」比喩がシリーズと同じフレーズか／例が主張を実際に支えているか |
| 4 | 人間らしい文章（語句レベル） | AI定型句（「〜することができます」「重要な要素」「効果的に」「最適化」「つまり、」等）／全角ダッシュ「——」・丸数字①②③の機械的多用／ヘッジ語尾の単調（「〜としています」「〜されています」への偏り）／助詞を削った電報調・無主語文 |
| 5 | 人間らしい文章（構成レベル） | 「AではなくB」型の反復／体言止めの警句連打／punch と caption の同一主張の二段反復／機械的な三点セット／同じ語尾の連続／notes に話者の実感・迷い（「だと思います」「正直」）があり、全部が断定と整理で構成されていないか。**多少冗長でも人が書いた温かみがあるか** |
| 6 | 構成と段階性 | 冒頭が 表紙→5層地図→学べること→章扉 か／第1章で定義（「〜とは何か」）が来てから詳細に進むか／難易度が段階的か／章の切れ目で「何が分かったか」を言えるか／伏線回収・closing が本編と対応しているか／「超入門」を名乗る厚みがあるか（01=53・02=72・03=66・04=55・05=48） |
| 7 | 図解・視覚の説明力 | 図が本文を実際に説明しているか（飾り画像でないか）／複雑な概念を文字だけで済ませていないか／図だけ英語ラベルでないか／図の要素数と本文の項目数が一致するか／投影で読める文字サイズか／下半分が空白のスライドが続かないか（レイアウト破綻自体は機械ゲート） |
| 8 | 実用性 | 読後に明日試せるもの（テンプレ・チェックリスト・Before/After）があるか／テンプレは置き換え箇所が［　］で明示されているか／「返ってきたら人が確認する」が一貫しているか／付録が本編から自然に参照されるか |
| 9 | シリーズ整合（01/02 基準） | タイトル・章扉・eyebrow・punch・学習ゴールスライドの体系が 01/02 と同じか／5層モデルの説明と注意書きが矛盾しないか／記号（全角コロン等）・文体（punch はです・ます、bullets は簡潔体）が揃っているか／01/02 の直後に流しても同じ人が作ったように見えるか |

## 出力（採点者）

指定された JSON ファイルに次の形式で書く（これ以外の出力は不要。点数は書かない）:

```json
{"schema": "findings-v2", "deck": "decks/03-harness-engineering", "grader": "g1",
 "probe": [{"concept": "ハーネス", "definition_from_slides": "…", "first_slide": 7, "ok": true}],
 "findings": [
   {"id": "f1", "item": 1, "severity": "大|中|小", "where": "slide-12", "quote": "実際の文言", "claim": "何が問題か1文", "fix_hint": "修正方針1行"}
 ],
 "notes": "全体所見3行以内"}
```
