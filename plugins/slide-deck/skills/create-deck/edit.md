# 既存デッキの編集・微修正

既存の `deck.json` を直す依頼（「この表をもう少し小さく」「3 枚目のタイトルを変えて」「色をブランドに合わせて」）の流れ。**作り直さず、直す場所だけを直す**。利用者が手で整えた他の箇所を壊さないため。

（`${CLAUDE_PLUGIN_ROOT}` は `SKILL.md` に書かれた実パスに読み替える。この補助ファイルでは変数が展開されない。）

## 流れ

1. `deck.json` を読み、直す対象のスライドを特定する。番号は deck.json の何枚目か（`slides` の並び）と、プレビュー PNG の番号（agenda の分割・凡例ページの自動挿入でずれる）を取り違えない。`check_visual.py <deck_dir> --json <file>` の `src` が対応表になる。
2. 依頼の種類で直し方を選ぶ。
   | 依頼 | 直し方 |
   |---|---|
   | 文言の変更・追加・削除 | 該当スライドの文字列を直す |
   | 文字が多い・窮屈 | まず内容（項目数・文の長さ・分割）。次に `meta.density` / スライドの `density`（talk / standard / read）。最後に `style` |
   | 中身が少ないスライドの文字が自動で大きくなる／語の途中の改行が入る（2.0.0 のままにしたい） | そのスライドに `autofit: false`（デッキ全体は `meta.autofit: false`）。改行を止めるのは `line_balance: false` か `style.wrap.enabled: false`（`autofit: false` でも止まる）。一部の領域だけなら、その領域の `size` を `style` に書く。2.0.0 に戻らない変化は README の「`autofit: false` でも戻らない変化と戻し方」 |
   | 位置・サイズ・フォント・色の具体的な指定 | 該当スライドの `style` に**差分だけ**書く（理由を一言添える）。デッキ全体なら `meta.layout_overrides` |
   | 配色・フォントのセットを変える | `meta.theme` を変える。新しいテーマなら `add-theme` |
   | 角丸・罫線・箱の雰囲気を変える | `meta.shape`（`classic` / `sharp` / `soft` / `editorial`）を変える。「もっと角ばった感じに」で**すでに `sharp`** なら shape ではもう変えられない。表紙の `left-band` の円の飾りは `sharp` で四角、`editorial` で角丸の四角になる（`classic` / `soft` は円。円を避けるなら `variant` を `center` などに替える。`references/schema/hero.md`） |
   | 「ここを目立たせたい」「表紙・章扉を印象的に」 | cards の `emphasis`、`variant` / `background`、`split`（`references/schema/hero.md`）。主役は 20 枚に 3〜5 枚（10 枚以下は 1〜2 枚）まで。既に多いなら増やさず、ほかの主役（締めの `contact` など）を通常に戻す。**すでに `split` の効果ページ**をもっと目立たせるなら、パネルは `kpi` だけにして `title` は足さない（両方書くと「主役は 1 つ」の警告）、`ratio` を 0.5 前後に上げてパネルを広げ、本文側のブロックを 1 つに絞る |
   | 「パターン（型）のスライドの文字をもう少し大きく」 | `style` は効かない（`style.body` は型を置く矩形を絞るだけで、文字は大きくならず警告も出ない）。`slots` の文を短くする・項目を減らす（型が全項目を同じ大きさにそろえ、文が短いほど大きくなる）。減らして下が空いた（`empty-bottom`）ら、`recipes.md` の「内容が薄いときの逃げ道」のとおりタイプか構成を替える |
   | 1 枚に詰め込んで文字が小さい（合成スライド） | ブロックを減らすか 2 枚に分ける。ブロックの文字サイズを `style.blocks.<タイプ>…` で固定するのは最後 |
   | 【要確認】を解消したい（確認が取れた） | 該当の文字列を確定した文に直し、マーカーを消す。再ビルドの `note: 要確認が N 件あります` の件数が減ったことと、残りの一覧（`lint_deck_text.py`）を報告する。確認が取れていない分は、作らず【要確認】のまま残す |
   | 色を変えたのに文字が読みにくい・ブランド色を変えたくない | 地の色の上で 4.5:1 に足りない文字色は、ビルドが自動で濃く（薄く）寄せる。意図して低コントラストにするときだけ、レイアウト JSON の `readable_pairs` の該当組を空にする（`references/themes.md`）。まず色の組を見直す |
   | 図解の配線・ラベル | `check_diagram.py` の指摘から 1 点だけ直す（`checks.md` の修理ループ） |
   | 全体を別の構成にしたい | 骨子（`outline.md`）から新規作成の流れに戻る。上書きは承認を取る（`approval-gates.md`） |
3. `build/` は直接編集しない。直すのは必ず `deck.json`。
4. `build_deck.py <deck_dir> --html` で再ビルドし、`preview_deck.py <deck_dir> <番号>` で**直したスライドだけ**目で確かめる。文字量・レイアウト・図解の配置を大きく変えたときは、`checks.md` の機械チェックも回し直す。
5. 目で確かめたら PPTX も作り直す（`build_deck.py <deck_dir>`）。`meta.date` を更新する。

## 守ること

- 利用者が `style` や `meta.layout_overrides` に書いた値は、依頼されない限り消さない。自動フィットは、明示された値を動かさない。
- 手を入れるたびに `style` が増えるのは、内容の側で解決できていないサイン。同じスライドを 2 回直しているなら、`style` を重ねずに文言・分割・タイプの変更を検討する。
- 「このデッキ全体を見直して」と言われたら、`review-deck` を使う。
