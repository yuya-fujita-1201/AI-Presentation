# rubric.md — ai-eng-05 グラフエンジニアリング超入門 の採点表

対象: `decks/ai-eng-05-graph-engineering/deck.json`（正本）と `build/preview/slide-NN.png`（実際のレンダリング結果）

各項目 **10点満点。目標値: 全項目 8 以上**（合計 56/70 以上かつ最低点 8）。
機械で測れるもの（ビルド成否・PPTX検証・枚数一致・画像欠落）はここに含めない。それらは機械ゲート側で見る。

想定読者: **AI初心者。チャットAIは触ったことがあるがエージェントは未経験。技術力は高くない業務担当者を含む。**

---

## ① 初心者への適合性

| 見るもの |
|---|
| スライド面（notes ではなく `title`/`punch`/`bullets`/`lead`/`rows`）に、初出で説明のない専門用語・カタカナ語・英語が残っていないか |
| 前方参照（まだ説明していない概念に依存した説明）がないか |
| 論文名・企業名・ベンチマーク名・金額などの固有名詞が、初心者にとって情報過多になっていないか |
| 非エンジニアが「自分の仕事の話だ」と感じられるか。コード・Git・コンパイラの話に寄りすぎていないか |

**8点の水準**: 頭から順に読んで、どのスライドでも「知らない言葉で止まる」ことがない。

## ② 事実の正確性と誠実さ

| 見るもの |
|---|
| 事実に反する記述がないか（外部で裏の取れる主張は裏を取る） |
| 断定できないことを断定していないか。伝聞・聞き取り・出典間の食い違いが、その旨と分かる書き方になっているか |
| 数字が「測定条件つきの証拠」として提示されているか。条件を落として一般化していないか |
| 製品仕様（Claude Code のサブエージェント・フック等）を、バージョン差を無視して断定していないか |
| 5層モデルが「本シリーズ独自の整理であって業界標準ではない」旨が、スライド面に明示されているか（01・04デッキと同じ扱い） |
| 出典が追えるか。04デッキ相当の出典スライドがあるか |

**8点の水準**: 誤りゼロ。断定しすぎがゼロ。読み手が主張ごとに出所へ辿れる。

## ③ 事例・比喩の適切さ

| 見るもの |
|---|
| 比喩が説明対象と構造的に対応しているか（読者が誤った理解をする比喩がないか） |
| 同じ概念に別々の比喩が当たって混乱していないか。比喩の総数が多すぎないか |
| 難所（DAG・隠れた依存・偽の依存・所有権・アンカー・失敗分類）に、**非エンジニアの業務**に寄せた具体例が付いているか |
| 事例が主張を実際に支えているか。章ごとの事例の偏りがないか |

**8点の水準**: 難所のすべてに具体例があり、そのうち過半が非エンジニアの業務例。

## ④ 人間らしい文章（最重要）

依頼者の要求そのまま:「**多少の冗長さを残してでも、人間が頑張って書いたような温かみや自然さがある表現を望む**」。
簡潔で整いすぎている＝減点。

| 見るもの |
|---|
| 体言止めの連打、対句・標語調の作りすぎがないか |
| 意味の薄いキャッチコピー（「〜という設計」「〜の本質」「〜という一点」）がないか |
| 助詞を削った電報調、主語の消えた無主語文がないか |
| `notes` の文末表現が単調でないか（「〜としています」「〜されています」への偏り） |
| 話者の実感・迷い・言い淀みが残っているか。全部が断定と整理で構成されていないか |
| 全角ダッシュ「——」や「①②③」の機械的な多用がないか |
| 01・04デッキの文体水準（`punch` が読める文になっている、`caption` に体温がある）に届いているか |

**8点の水準**: 通しで読んで「人が書いた講義資料」に読める。標語の連打で息が詰まる箇所がない。

## ⑤ 構成と段階性

依頼者から明示された要求。

| 見るもの |
|---|
| **第1章で「グラフとは何か（丸と矢印）」「それをエンジニアリングするとは何か」を丁寧に説明しているか。** 流行語の起源やジョーク説より先に、定義が来ているか |
| **ループエンジニアリングとグラフエンジニアリングの対比が、冒頭に専用のスライドとして置かれているか。** 04デッキが第1章に「チャットAIとどこが違うのか」＋「焦点の違い（表）」を持つのと同じ水準か |
| 重要ワード（ノード・エッジ・状態・迂回路・DAG・依存・並列・オーケストレーション・所有権・検証ゲート）を、一つずつ順に深められる並びか |
| いきなりテクニカルにしていないか。難易度が段階的に上がっているか |
| 章のバランス。前で振った伏線が回収されているか。クロージングが本編と対応しているか |
| 「超入門」を名乗るのに枚数・厚みが足りているか（実測: 01=53枚、03=66枚、04=55枚） |

**8点の水準**: 初見の読者が、章の切れ目で迷わず、各章の終わりに「何が分かったか」を言える。

## ⑥ 図解・視覚の説明力

| 見るもの |
|---|
| 挿絵が本文を**実際に説明している図解**か、内容と無関係な**飾り**か |
| 概念が複雑なのに文字だけで済ませているスライドがないか（DAG・偽の依存・隠れた依存・ワークフロー型・所有権・検証ゲート・失敗分類） |
| 文字切れ・重なり・はみ出し・表の崩れがないか |
| 投影して読める文字サイズか。下半分が空白のスライドが繰り返されていないか |
| 配色の一貫性 |

**8点の水準**: 難所のスライドで、図を見ただけで主張の骨格が分かる。飾り画像が難所に残っていない。

## ⑦ シリーズ整合

| 見るもの |
|---|
| タイトルが 01「プロンプトエンジニアリング超入門」・04「ループエンジニアリング超入門」と揃っているか |

| 5層モデルの説明・注意書きが 01・04 と矛盾していないか |
| 記号の使い方（全角コロン「：」など）が揃っているか |

**8点の水準**: 04 の直後に流しても、同じ人が作った同じシリーズに見える。
